# Accounts and Sync Pro

## Architecture and plan

The hosted backend is the `syncapp` Supabase project (`iyipvwlhiwfaeyfoyakr`) in Frankfurt (`eu-central-1`), in the selected `Project 1` organization. This is not a local database. Migration SQL and function sources are versioned in this repository.

Free includes all existing local routines, timer, music controls, activity and guest mode. Accounts use email/password with confirmation, recovery, signout and deletion. Optional Apple/Google sign-in is behind explicit configuration flags. Spotify sign-in remains separate from the Sync account.

Accepted but unfinished recovery forms now retain a local marker in the same secure native storage as Auth, bound to the user's UUID and JWT `session_id`. This marker only restores UI state; it grants no authorization and copies no tokens. Marker persistence is best effort, hydration waits at most 1.5 seconds, and storage failure does not invalidate an accepted link or password update. Stale bootstrap results cannot replace newer Auth events, and an old password-update completion cannot dismiss a newer recovery. These changes have offline coverage; real reset completion and native recovery across process termination still require validation.

The pinned Supabase 2.119.0 client uses `processLock` alongside the app's explicit account-operation queue. Real SDK regressions reproduce an unlocked password update overwriting tokens rotated by `getSession`, `refreshSession` or an automatic refresh tick; the lock prevents that race. Auth event callbacks stay synchronous and do not call Auth again. The SDK deprecates its custom-lock option for v3: revisit this workaround and rerun those regressions during that migration, following the [lockless coordination migration guide](https://github.com/supabase/supabase-js/blob/master/packages/core/auth-js/migrations/lockless-coordination.md). No SDK upgrade was made.

Sync Pro adds an ad-free experience, private cloud backup and cross-device synchronization of routines, recent activity history (normally the latest 100 saved sessions), bio, social links and locally saved posts. Merged guest imports can contain more activity records; the backup size limit still applies. Imported audio and profile photos remain device-local; routines retain their track metadata so files can be reselected on other devices. Pulling metadata back onto the original device preserves its matching local audio references. No public social network or server-side music streaming is introduced.

Free accounts and guests can receive a labelled Discover banner and preloaded full-screen ads before a NEW session or on explicit Continue after an ended-session summary. The user confirmed there must be no advertising during active sessions, including rest and pause. Resume, phase skips and arbitrary tab changes never trigger an ad. Discover remains outside the feed scroll and is suppressed during search/details, empty feeds, overlays, workouts and audio activity. Full-screen ads require two distinct real actions before the first and every subsequent presentation, plus a separate 120-second cooldown. Start never waits for an ad to load; no-fill is skipped and late loading cannot interrupt a session. Shared consent/presentation barriers and fresh identity/routine/foreground checks run before the timer and music start. Pro suppresses both ad formats, preparation and requests, including automatic consent/initialization; unknown or pending access never counts as confirmed Free. The free core remains available without ad inventory. See [AdMob setup](admob-setup.md) for configuration and validation status.

Monthly and annual products map to a single RevenueCat entitlement named `sync_pro` (the internal database access key remains `pro`). The owner selected US$2.99/month and US$18/year, with no trial in the first release. Both prices are saved in App Store Connect, but no product or price has been published. The existing RevenueCat Test Store onboarding catalog is not a live App Store/Google Play product catalog. Store regional prices must be configured and approved in the merchant's console; the paywall always uses actual localized prices from the store, never these draft amounts.

A store purchase awaiting backend confirmation remains pending when server verification fails. This neither grants Pro nor permits a repeated checkout. SDK configuration rejects private/wrong-platform keys and permits Test Store keys only in debug development; preview and production require platform-specific public keys. [RevenueCat documents that Test Store keys must not be submitted in release builds](https://www.revenuecat.com/docs/test-and-launch/sandbox/test-store).

## Data behavior

All personal device keys and music credentials are scoped to an immutable account ID. Signing out returns to a separate guest space. Account switches remount data/workout providers so the old state is not shown to the next user. Deleting an account requires a sign-in in the last 15 minutes, confirmation, server deletion, then a closed/drained local scope. Account deletion does not cancel an Apple/Google subscription; the UI offers its store management link before deletion. Purchase restoration is intended to transfer the paid entitlement to the new signed-in account, not to transfer the former account's private routines, profile or backups. The account data isolation rules remain unchanged.

The prepared review source further separates immutable production/review namespaces. Account consumers wait for a valid scope matching the current user; a trusted cached scope can open that namespace offline without granting cloud or Pro access. Unknown-scope failure offers a separate Retry and normal Auth sign-out to use Sync as a guest; local-read recovery retains its own Retry. No production fallback, automatic temporary/guest import or data removal is used. Delayed Retry/sign-out callbacks from a different user are rejected. Review accounts cannot import or clean up guest records; ordinary production manual import remains available.

Existing guest records are imported explicitly from Profile once per device installation. Import waits for queued guest saves and writes a durable account claim before the first copy, so interruption cannot let another account claim the same records. The same claimant can resume partial copying or completed-copy cleanup; existing account records win on ID collisions. Guest sources are removed only after all account copies and the ownership marker are durable. Failed cleanup retries preserve later account and guest edits. Deletion closes the scope immediately, drains/wipes its account writes, then releases only its unfinished claim and cleanup journal; completed-import ownership remains. Closed-scope checks guard awaited copy/ownership steps and the destructive cleanup boundary. Music credentials are never imported or backed up; reconnect Spotify in the signed-in account.

Offline writes remain in account-scoped storage. Sync uploads use a persisted dirty counter and server revision. If another device changed the cloud backup while this device has edits, the UI asks which version to keep. Cloud replacement keeps a local rollback journal of exact device values and metadata until commit. Before commit, a failed or interrupted replacement recovers before later reads/writes, preserving local audio references and queued edits; the journal stays local and is never uploaded. A separate recovery snapshot is retained. Synchronization pauses during active or paused workouts and rechecks eligibility after asynchronous steps. If a complete commit wins a pause and a new rollback journal cannot be persisted, the complete cloud copy stays intact; its consumer reload is deferred until idle. A stopped engine never applies that deferred reload. If a workout interrupts an unresolved copy choice, the next idle sync restores the choice controls without silently selecting or fetching another copy. Media files, credentials, tokens and passwords are excluded from cloud backups. Background sync retries on foreground and at one-minute intervals while Pro is active.
